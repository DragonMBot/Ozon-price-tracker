# Анализ цен на Ozon — Firefox + Python 3.14

Локальный прототип трекера цен. Расширение Firefox отвечает за интерфейс; Python API работает отдельным процессом и хранит пользователей, товары и измерения в SQLite. Внешняя аналитическая библиотека для графиков не нужна: график рисуется SVG-кодом, а при наведении показывает цену и точное время измерения.

## Возможности

- Регистрация и вход по email/паролю. Пароли не хранятся в открытом виде: используются `hashlib.scrypt` с индивидуальной солью. Сессия — подписанный HMAC-токен со сроком действия 24 часа.
- Локальная база SQLite: `data/price_tracker.sqlite3`.
- Отдельные списки товаров для каждого аккаунта, защита от повторного добавления одного Ozon ID в список пользователя.
- Добавление по числовому ID; товар сохраняется только после успешного извлечения названия и цены.
- История измерений цен; диапазоны графика 7, 30 и 180 дней, сетка, подписи дат, минимум, текущее значение, изменение от первого к последнему измерению и всплывающая подсказка с точными датой/временем и ценой.
- Плановое обновление каждые 12 часов, когда локальный сервер запущен. Также есть кнопка ручного обновления.
- Логи Python и API: `logs/application.log` и консоль. Логи ограничены по размеру и ротируются. Ошибки интерфейса отображаются в консоли Firefox и, если сервер доступен, передаются в файл приложения. Пароли и токены в логи не записываются.

## 1. Запуск backend

Нужен **Python 3.14**. При первом запуске создаётся виртуальное окружение и устанавливаются зависимости.

### Windows PowerShell

```powershell
cd путь\к\ozon-price-tracker
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\run.ps1
```

Либо выполнить вручную:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m app.main
```

### macOS / Linux

```sh
cd /path/to/ozon-price-tracker
./run.sh
```

Оставьте окно терминала открытым: оно поддерживает локальный API и плановые обновления. Для проверки откройте `http://127.0.0.1:8765/api/health`; ответ должен содержать `"status":"ok"`. Документация API доступна на `http://127.0.0.1:8765/docs`.

## 2. Установка расширения в Firefox для разработки

1. Запустите backend и убедитесь, что `/api/health` доступен.
2. Откройте в Firefox `about:debugging#/runtime/this-firefox`.
3. Нажмите **«Загрузить временное дополнение…»**.
4. Выберите `extension/manifest.json` в каталоге проекта.
5. Нажмите значок расширения в панели браузера — откроется панель в новой вкладке.
6. Зарегистрируйте локальный аккаунт, затем добавляйте товары.

Это временная установка разработчика: после полного перезапуска Firefox может потребоваться загрузить дополнение снова. Для постоянной установки и распространения нужна упаковка и подписание дополнения в Mozilla Add-ons.

## 3. Проверка без запуска парсера Ozon

Для проверки API, регистрации/входа, SQLite, истории цен, изоляции пользователей и удаления товаров используйте специальный сценарий. Он **не запускает браузер и не отправляет сетевых запросов к Ozon**. В тестах функция получения товара подменяется контролируемым фиктивным ответом.

### Автоматический скрипт (рекомендуется)

Из корневой папки проекта в активированном виртуальном окружении:

```sh
python scripts/run_checks.py
```

Скрипт попросит email аккаунта, затем попросит подтвердить добавление демонстрационных записей. Будут запущены `test_api.py` и `test_non_parser.py`; тесты из `test_core.py`, проверяющие сам HTML-парсер, намеренно не запускаются. Если все проверки пройдены, для указанного email будут подготовлены три фиктивных товара с восемью ценовыми точками у каждого. Результат сохранится в `logs/test-report-<дата>.json`.

- Если email уже зарегистрирован, пароль не меняется; фиктивные товары добавятся в этот аккаунт.
- Если email новый, будет создан локальный тестовый аккаунт. Временный пароль показывается в консоли только при первом создании — сохраните его, чтобы войти в расширение. Пароль в JSON-отчёт и логи не записывается.
- Фиктивные товары остаются в базе, пока вы их не удалите. Названия имеют префикс `[ТЕСТОВЫЕ ДАННЫЕ]`, цены и графики являются синтетическими и не отражают реальные цены Ozon.

### Проверка прямо в Firefox

1. Запустите backend через `run.ps1` (Windows) или `run.sh` (macOS/Linux). Эти скрипты включают локальный режим тестирования `OZON_ENABLE_TEST_TOOLS=1`.
2. Войдите в расширении в тот аккаунт, которому нужно добавить демо-данные.
3. Нажмите **«Проверить приложение»** справа в шапке и подтвердите email аккаунта.
4. Расширение проверит доступность API, текущую сессию, создание и чтение фиктивных товаров, истории за 7/30/180 дней, защиту от дублей, требование авторизации и отрисовку карточек. Ожидаемые результаты отображаются в том же окне. Парсер Ozon не вызывается.
5. После теста фиктивные товары останутся в общем списке. Удалите их кнопкой удаления, если они больше не нужны.

Инструмент в расширении разрешает засевать фиктивные данные только для email текущей сессии. Чтобы подготовить данные другому email, используйте CLI-скрипт — он попросит подтверждение перед изменением SQLite. Если вы запускаете backend вручную командой `python -m app.main`, функция тестовых данных по умолчанию отключена; для локальной диагностики установите `OZON_ENABLE_TEST_TOOLS=1`. Не включайте этот флаг в серверной/публичной установке.

### Запустить только не-парсерные автоматические тесты вручную

```sh
python -m unittest discover -s tests -p test_api.py -v
python -m unittest discover -s tests -p test_non_parser.py -v
```

Обычная команда `python -m unittest discover -s tests -v` дополнительно запускает старые тесты HTML-парсера из `test_core.py`; её не используйте, если хотите проверить только остальные компоненты.

## 4. Как работает обновление цен

- Первая цена записывается сразу после успешного добавления товара.
- Каждые 12 часов backend обновляет список товаров. Сетевые вызовы выполняются последовательно, чтобы не создавать всплеск запросов.
- При успехе создаётся новое измерение цены, обновляются название и текущая цена.
- При сетевой ошибке, ограничении частоты запросов или невозможности распознать цену запись товара не удаляется; ошибка сохраняется в карточке и логе. Старое достоверное значение остаётся текущим, пока не будет получено новое.
- Обновление работает только пока backend запущен. После остановки/сна компьютера запросы не выполняются; при следующем старте отсчёт двенадцати часов начинается заново.

## Диагностика ошибок HTTP при добавлении товара

HTTP-статус локального API теперь различает типы отказа: `422` означает, что HTML загрузился, но ID/название/цена не прошли проверку или цена не распознана; `424` означает, что источник отказал в доступе или показал CAPTCHA; `504` — тайм-аут загрузки; `429` — ограничение частоты запросов; `502` — ошибка upstream-сервера или неизвестный сетевой сбой. В JSON-поле `detail` дополнительно остаются `code`, `provider`, исходный `http_status` Ozon и безопасные метаданные.

Поэтому если браузер открывает страницу, но добавление товара не проходит, это не обязательно означает, что Ozon вернул HTTP 502: HTML мог загрузиться без цены, которую парсер умеет надёжно распознать. Проверьте сообщение в окне добавления товара, затем `logs/application.log` и локальный снимок `parser_output/page.html`. Сам HTML не отправляется в логи или UI API.

## 5. Загрузка страницы и сохранение HTML

При добавлении или обновлении товара backend открывает публичную карточку обычным Playwright Chromium и ждёт, пока главный фрейм перестанет навигировать. Перед разбором программа получает `page.content()` и атомарно сохраняет полный HTML в `parser_output/page.html` (путь можно изменить переменной `OZON_HTML_OUTPUT`). В API и логи содержимое HTML не передаётся; в журнале остаются только безопасные диагностические метаданные.

- Для стабильности используется пауза в 8 секунд после последней навигации, максимальное ожидание стабилизации — 60 секунд и не более 5 попыток прочитать HTML, если навигация прервала чтение.
- Добавление и ручное обновление товара имеют отдельный тайм-аут интерфейса 140 секунд. Backend ограничивает всю операцию парсинга 125 секундами и возвращает структурированную ошибку, если страница не успела обработаться. Обычные API-запросы по-прежнему имеют тайм-аут 30 секунд.
- Страница сохраняется до проверки HTTP-кода и до разбора; поэтому при 403/антибот-странице локально можно увидеть, какой HTML вернул источник. Это не означает, что данные удалось получить.
- При `403`, CAPTCHA или другой проверке доступа программа прекращает извлечение и не пытается автоматически проходить проверку, маскировать отпечаток, менять IP или повторять заблокированный запрос.
- `429` и `5xx` отображаются отдельно; автоматического повтора внутри одного запроса нет. Планировщик попробует обновить цену в следующем плановом цикле через 12 часов.
- Цена берётся только из JSON-LD, метаданных или выделенного ценового блока. Если достоверное название/цена не найдены, новая запись не создаётся.

Для работы нужен обычный Playwright Chromium. При первом запуске установочный скрипт выполняет `python -m playwright install chromium`. Браузер запускается в видимом режиме, как в примере HTML-снимка; на компьютере должна быть доступна графическая сессия.

## Данные и безопасность локального режима

- API слушает только `127.0.0.1`, не выставляется в локальную сеть.
- Секрет подписи токена создаётся в `data/secret.key`; не удаляйте его без необходимости — существующие сессии перестанут проходить проверку. Файл базы и секрет не нужно публиковать.
- В этой версии нет восстановления пароля, серверной регистрации через интернет, синхронизации между компьютерами или многофакторной аутентификации — это локальная база, а не облачный сервис.
- Держите зависимости обновлёнными и проверяйте соблюдение правил использования Ozon для своего сценария.

## Если появляется «Локальный сервер не ответил вовремя»

- Убедитесь, что окно PowerShell/терминала с `python -m app.main` всё ещё открыто.
- Откройте `http://127.0.0.1:8765/api/health`: если эта ссылка не отвечает, проблема в запуске backend, а не в извлечении цены.
- Если health отвечает, но добавление товара завершается ошибкой, проверьте `logs/application.log` и `parser_output/page.html`. Новая версия ждёт завершения операции парсинга до 125 секунд и отдельно сообщает о превышении общего срока.
- Не запускайте несколько копий backend одновременно: это может привести к конфликту портов/баз данных и затруднить диагностику.
